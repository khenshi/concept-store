# Milestone 1: Prisma 7 Configuration

## Scope

This infrastructure update aligns the backend with Prisma 7's datasource and client configuration model:

- Prisma CLI and client upgraded to 7.9.1
- migration connection URL moved from `schema.prisma` to `prisma.config.ts`
- direct PostgreSQL connections use `@prisma/adapter-pg`
- generated client uses the `prisma-client` generator with an explicit output directory

It does not change the application data model, existing migrations, organization behavior, or tenant authorization rules.

## Migration configuration

`backend/prisma.config.ts` loads `.env` and supplies `DATABASE_URL` to Prisma migration commands:

```ts
export default defineConfig({
  schema: 'prisma/schema.prisma',
  migrations: { path: 'prisma/migrations' },
  datasource: { url: env('DATABASE_URL') },
});
```

The datasource block in `schema.prisma` now declares only the PostgreSQL provider. Prisma 7 no longer accepts `url = env("DATABASE_URL")` in that block.

Because Prisma loads `prisma.config.ts` during client generation, `.env` should be created before running `npm install`, whose postinstall script generates the client.

## Runtime connection

`PrismaService` constructs `PrismaPg` from the validated `DATABASE_URL` and passes it to `PrismaClient` as the direct database adapter. NestJS configuration validation remains authoritative at application startup.

The generated client is written to `backend/src/generated/prisma` and excluded from Git and ESLint. It is regenerated by `npm install` or `npm run prisma:generate`.

The generator uses CommonJS output to match the backend's current NestJS build. Jest maps generated `.js` import specifiers back to their TypeScript source during tests. The CLI-only `prisma.config.ts` is excluded from the Nest production build so the application entry point remains `dist/main.js`.

## Commands

Run from `backend/`:

```bash
npm run prisma:generate
npm run prisma:validate
npm run prisma:migrate:dev
npm run prisma:migrate:deploy
```

## Validation performed

- Prisma 7 client generation passed.
- Prisma schema validation passed using `prisma.config.ts`.
- Both existing migrations applied successfully to a clean PostgreSQL database.
- Formatting, ESLint, 26 unit tests, and the production build passed.
- The production entry point remained `dist/main.js`.
- The compiled backend connected through `@prisma/adapter-pg`.
- Registration and organization creation both returned HTTP `201` against PostgreSQL.

## Assumptions and limitations

- The backend uses a direct PostgreSQL connection rather than Prisma Accelerate.
- Generated Prisma source is not committed and must be generated during installation or deployment.
- Existing SQL migrations remain valid and were not rewritten.
